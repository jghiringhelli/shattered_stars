# Internationalisation (i18n)

State: **ready, not translated.** A typed message-catalog layer exists (`src/i18n`), English is the source
language, and the welcome and feedback dialogs are migrated as the pattern. Everything else is still inline
English.

## Using it

```ts
import { t } from "../../i18n";

t("welcome.title");                                     // "WELCOME, TESTER"
t("feedback.status.saved", { fileName, trimmed: "" });  // placeholders are typed: exactly {fileName} and {trimmed}
```

- Add the English text to `src/i18n/messages.en.ts` (the source catalog) and call `t("key")`. A typo in a key or a
  missing/extra placeholder does not compile.
- Keys are `area.screen.purpose` (`feedback.how.step2`). Use `PlainMessageKey` for tables of placeholder-free keys.
- One message per sentence. Never concatenate translated pieces (`t("a") + " " + t("b")`): word order differs
  between languages; use a placeholder instead.
- Plurals and number formats: not needed yet; when the first plural appears add `Intl.PluralRules` based
  variants (`key.one` / `key.other`) in `translator.ts`.
- Locale: `initLocale(window)` runs at boot. It reads `?lang=xx`, then `navigator.languages`, falls back to `en`
  and sets `<html lang>`. A persisted setting (SettingsScene > language) is the planned next step: add a
  `locale` field to `settingsSchema.ts` and pass it as the first candidate of `resolveLocale`.
- Guards: `tests/unit/i18n/i18n.test.ts` fails when a `t("...")` key is not in the catalog, when a catalog key is
  unused, and (once other locales exist) when a translation changes the placeholders of the English text.

## Adding a language

1. Add the code to `SUPPORTED_LOCALES` in `src/i18n/translator.ts` and a catalog `src/i18n/messages.<code>.ts`
   typed `Partial<MessageCatalog>` (missing keys fall back to English); register it in `CATALOGS`.
2. Check the fonts: `holoFont` uses Latin glyphs. Accents are fine; CJK/Arabic need a fallback family and, for
   right-to-left scripts, mirrored layouts (not supported).
3. Run the game with `?lang=<code>` and walk the migrated screens.

## Externalising the rest

Where the text lives (audit of 2026-10-14):

| Where | Size | Approach |
|---|---|---|
| `src/data/**` (ships, pilots, cards, campaign, survival events, creatures, lore) | about 2,300 string properties in 106 files (`npm run i18n:extract`) | keyed by **id**, not by sentence: `data.<file>.<id>.<property>`; the data keeps ids and numbers, the text is looked up (`dataText(id, "name")`) |
| Scenes and `src/ui/**` inline literals (`.text(...)`, DOM `h(...)`) | about 140 call sites in 73 files plus the DOM dialogs | migrate screen by screen like the welcome dialog |
| Tutorials, briefings, mission scripts | prose | one catalog namespace per mission/lesson; review with the narrative owner (lore glossary applies: psionics, riggers, Snap Turn / Hook Loop / Knife Roll) |

`npm run i18n:extract` scans `src/data` for string properties named `name`, `title`, `description`, `text`, `label`,
`summary`, `flavor`, `lore`, `briefing`, `tooltip`, `hint`, `tagline`, `message`, `objective` and prints a count per file;
`npm run i18n:extract -- --json out.json` writes the proposed `{ key: text }` catalog. It never edits code.

Suggested order (each step one PR, e2e and `test:skill` green):

1. Main menu entries and footer, Settings tabs, pause menu, results screens (highest traffic).
2. Tutorial (Flight School) and tooltips.
3. Data text by domain with a generated catalog per area (`locales/en/ships.json`, `upgrades.json`, ...), loaded on demand
   with the lazy scene chunks so the first menu does not pay for it (see `src/scenes/lazy`).
4. Campaign and Survival prose last; keep lore glossary terms in a shared glossary file for translators.
5. ESLint `no-restricted-syntax` rule that flags string literals in `.text(` calls once the screens are migrated.

Do not translate: ids, save-file keys, telemetry event names, e2e selectors that read labels (tests run in `en`),
and the lore terms that the distancing test guards (`tests/unit/lore/distancing.test.ts`).
